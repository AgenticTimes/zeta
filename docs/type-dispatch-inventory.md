# 类型判断散落点清单（F.1 审计，批次 814 产出）

这是"把类型判断收拢成一套"的第一步：先把散落在各处的判断点数清楚、
列出来。此清单同时服务三件事：删无用代码要查它、给值带类型标记的
验收要查它、类型检查器独立更要查它。

数据采集口径：`grep -rn` 全 `src/`（2026-10-02，含车道在制改动）。

## 总览：五类判断点，共约 228 处

| 判断种类 | 含义 | 处数 | 分布 |
|---|---|---|---|
| PyDynamic 判定 | "这个值类型还不知道"的分支处理 | **79** | gen.rs 45、resolver.rs 22、types/mod.rs 5、其余 7 |
| map/dict 字符串比较 | "这是字典吗"（两种拼写等价规则手写） | **22** | gen.rs 16、resolver.rs 3、typecheck_new.rs 2、types 1 |
| NoneValue/NoneLit 判定 | "这个值是空值"（804/806 新面） | **36** | gen.rs 与 resolver.rs |
| 值标记读写 | 给值附带/读取类型标记（767-808 的正式机制） | **12** | gen.rs |
| I64 槽兜底 | 类型推不出就默认整数——**"值对类型丢"的最高风险位** | **76** | 几乎全在 gen.rs |

## 每类的收拢目标

1. **PyDynamic（79 处）**——大部分形状是同一句话：
   `matches!(t, Some(Type::I64) | Some(Type::PyDynamic))`（"类型未知就按
   动态处理"）。收拢为一个谓词 `Type::is_dynamic_slot()`，逐处替换。
   替换时逐处核对语义（有些是"未知则放弃"，有些是"未知则分派"——谓词
   相同、后续动作不同，不能一刀切）。

2. **map/dict（22 处）**——直接换 `Type::is_map()`（types 层新增）。
   这是最机械的一类，可脚本化。

3. **NoneValue/NoneLit（36 处）**——已经比较集中（804/806 刚写的），
   需要的是一个统一的"空值渲染/存储"入口，替代 print 臂、fromkeys 臂
   各自的按型渲染代码。

4. **值标记读写（12 处）**——这是应该**保留并成为唯一机制**的一类：
   写侧 `zeta_map_set_tag`、读侧 `slot_tags` + `zeta_map_value_tag`。
   目标不是删，而是让 1、3 两类逐步"改读标记"而不是"猜类型"。

5. **I64 兜底（76 处）**——最危险、也最不能机械替换的一类。每一处都是
   一个"编译器不知道类型时的决定"：有的正确（确实该当整数）、有的就是
   静默错值的种子。**逐处裁决**才是正解，本清单就是裁决的工作清单。

## 三处"规则源头"（判定逻辑的定义点）

| 位置 | 管什么 |
|---|---|
| `resolver.rs:1498` classify | 函数返回值的证据分类（str/f64/i64/字典旗标） |
| `typecheck.rs:359` string_to_type | 类型标注文本 → Type 的解析入口 |
| `mir.rs:61` signature_ret_ty | 函数返回类型的唯一裁决（批 399 建立） |

类型检查器独立的实质 = 把这三处的规则搬进独立模块、让 gen.rs 变成
纯消费者。上表 228 处散点收拢后，这一步才有干净的着手面。

## 建议的执行顺序

1. `is_map()` + `is_dynamic_slot()` 两个谓词落地（机械，日级内）；
2. 家族拆文件时顺手消灭各文件内的重复判定（顺手，不单独立批）；
3. I64 兜底 76 处逐处裁决（长周期，随修 bug 的批次自然推进）；
4. 三处规则源头搬家（等 1–3 完成后动手，那才是"类型检查器独立"本体）。
