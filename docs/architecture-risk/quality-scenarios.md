# 质量属性场景 — 扩展性与可靠性

> 取证日期 2026-09-25　|　配套：`architecture-review.md`（R#）、`remediation-plan.md`（P#）
> 每个场景给出：刺激 → 响应 → 度量口径 → 当前证据状态。未测的明确标"未建立基线"。

## S1 可扩展性 — 加一个表达式构造

- **刺激**：需要支持一个新的表达式形态（例：某个 Python 内建的方法调用）。
- **当前响应**：改 `src/middle/mir/gen.rs` 的 `lower_expr`（`gen.rs:3527-13898`，单函数 10,371 行），在 225 个 `_ =>` 兜底臂的包围中新增一条臂。
- **度量**：新增一条构造所触碰的**文件数**与**函数数**；该 commit 是否可独立回滚。
- **目标**：触碰 1 个新模块 + 1 处枚举分发；可独立 revert。
- **证据状态**：当前值 = 1 文件 / 1 函数（因为无法绕开）。基线由 `git log --name-only --since=2026-09-01` 实测：255/789 commit 落同一文件。
- **验收**：拆分后连续 3 个新构造的 commit 均不触碰 `gen.rs`。→ P1

## S2 可靠性 — 不支持的构造必须显式失败

- **刺激**：输入含 lowering 未实现的构造。
- **当前响应**：命中兜底臂。`gen.rs` 有 225 个 `_ =>`，显式 "not implemented" 仅 3 处。语料侧实测：`zeta_src/middle/mir/gen.z:250` 丢语句、`:386-389` 落成 `MirExpr::Lit(0)` 并记 `"i64"`。
- **度量**：注入 N 个未支持构造，统计 **报错数 / 静默错值数 / panic 数** 三分类。
- **目标**：静默错值 = 0（要么诊断，要么显式拒绝并留痕）。
- **证据状态**：**未建立基线** — 本次未做注入实验。这是最该先补的度量，因为它决定 R2 的真实损害量。
- **验收**：新增注入夹具（每条一个构造），门禁记录三分类计数。→ P0-b、P3

## S3 可用性（诊断质量）— codegen 失败不得崩进程

- **刺激**：codegen 遇到内部假设不成立（例：符号解析不出）。
- **当前响应**：panic。`src/backend/codegen/codegen.rs` 53 个 `fn`、**0 个返回 `Result`**、507 个生产 `.unwrap()`（文件内无 `#[cfg(test)]`）。旁证：批次 406（`94007ada`）是"整程序链接失败"级缺陷。
- **度量**：编译失败时输出**含 file:line 诊断**的比例；`exit code != 0 且 stderr 无 panic 回溯`的比例。
- **目标**：用户输入的编译失败 0 panic。
- **证据状态**：静态证据充分（上表），运行期未测。
- **验收**：`.unwrap()` 计数下降且 `-> Result<` 从 0 起增；配一条"故意坏输入不 panic"的集成测试。→ P2

## S4 可维护性 — 变更可隔离

- **刺激**：一次改动只想影响一个 pass。
- **当前响应**：做不到。`frontend ↔ middle` 成环（f→m 13 处 / m→f 18 处），且 churn 前三文件吃掉全部 commit 的 50%（255+76+61 / 789）。
- **度量**：`src/frontend/**` 内 `use crate::middle` 命中数；单 commit 跨层数中位数。
- **目标**：环命中数 = 0。
- **证据状态**：当前值已实测（5 个文件：`frontend/borrow.rs`、`borrow_enhanced.rs`、`parser/identity_type.rs`、`identity_ownership.rs`、`identity_ownership/tests.rs`）。
- **验收**：`grep -rn 'use crate::middle' src/frontend --include='*.rs'` 为空。→ P4

## S5 可测试性 / 可用性 — 门禁可在开发机复现，且不单点

- **刺激**：(a) 开发者在本地（非该 runner）验证一条语料用例不回归；(b) 那台 runner 下线维护。
- **当前响应**：**5 个 CI job 全部 `runs-on: [self-hosted, galaxy, wsl2, x86-64]`**（`ci.yml:17,28,38,55,71`）。804 个 `.z` 夹具的唯一执行者 `tools/run_all.sh` 挂在 `baselines`（`:90`）。本评审机为 darwin/arm64。
- **度量**：(a) runner 近 30 天可用时长 / 因环境原因失败的 job 数；(b) 在第二架构上跑通 `run_all.sh` 的成功率。
- **目标**：至少一条可在任意开发机复现的等价子集（明确记录 x86-64-only 清单）；`runs-on` 至少拆出一个 hosted runner 承载 `check`。
- **证据状态**：runner 标签与 job 接线已实测（`grep runs-on | uniq -c` = 5×同一标签）。**未测**：`run_all.sh` 在 arm64 上是否可用（可能只是被 `|| true` 静默降级）、该 runner 的历史可用性。
- **验收**：本机跑一次并记录逐子门 rc；或 CI 中出现第二个不同的 `runs-on` 标签。→ P5、P0-a

## S6 可测试性 — 子门不得静默 0 命中

- **刺激**：`run_all.sh` 某子门因 glob/路径变动命中 0 条。
- **当前响应**：文件内多处 `|| true` 与 `grep -c ... || true`（`:242-243,266-267,288-289,311`）→ 0 命中与"跳过"难区分。
- **度量**：故意让一个子门 0 命中，job 是否仍绿。
- **目标**：0 命中 = 红（除非显式 pin 并在报告中标注 pinned 数）。
- **证据状态**：**未测**（需故意破坏一次）。参见 review §四 A4。语料侧已有正面先例：`selfhost_compile.sh` 对钉住的 4 例"若反而通过则失败"。→ P0-a

## S7 可维护性 — 权威文档不得比代码旧

- **刺激**：新协作者/agent 读 `docs/ARCHITECTURE-REVIEW-2026-09.md` 判断现状。
- **当前响应**：该文档（09-19）称"python_style 与官方 194 均未进 CI"——已被 `ci.yml:90` 推翻（接线于 `1e79439a`，09-23，标题"删掉两个说谎的步骤"）；其 `src/` 220 文件 / gen.rs 10,995 行 vs 实测 172 / 14,644。
- **度量**：文档内每个精确整数断言是否带取证日期与口径；可重跑脚本 `docs/architecture-health/check-arch-claims.py` 的退出码。
- **目标**：文档里的精确数字要么可重跑校验，要么改成区间 + 口径。
- **验收**：把 `check-arch-claims.py` 纳入 CI（health 报告的 follow-up 已这么建议）。→ P6

## S8 可扩展性 — 加一个 Python 内建函数

- **刺激**：新增一个 `py_*` 内建。
- **当前响应**：`pylib/registry.txt` → `gen_from_registry.py --emit`（生成物，有 `git diff --exit-code` 门）→ 还要在 `resolver.rs`(133) / `gen.rs`(264) / `codegen.rs`(57) 手写特判，三处无一致性门。全仓 `py_` 共 862 处。
- **度量**：新增一个内建所需手写点数量；是否有"registry 有条目但 lowering 无对应臂"的检测。
- **目标**：手写点 = 0 或 1；未接线条目在 CI 报错。
- **证据状态**：分布已实测；**未测**：单个内建实际需几处改动（需做一次干跑统计）。项目记忆的"228 处上限"现为 264。→ P7

## 未建基线的汇总

S2（未支持构造三分类）、S5（arm64 可用性）、S6（子门 0 命中）、S8（单内建手写点数）、A3（ABI 名字瀑布）本次都**只有静态证据、没有运行期读数**。P0 就是把这些读数建起来——在给出修复优先级之前，先让损害量可测。
